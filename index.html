NTR-Net: Neighbourhood Transform Refinement Network

A lightweight low-light enhancement network that predicts a grid of local colour transforms instead of generating every pixel.

What I did

  • Designed the network: 0.94 M parameters, 5.56 GMACs at 256×256, about 2.8× less compute than RetinexFormer.
  • Ran a headroom study first: a perfect 16×16×8 transform grid reaches 30.3 dB on LOL-v1, so the idea has real room to grow.
  • Error analysis with oracle corrections showed most remaining error is per-image brightness and tone, not noise (+0.1 dB).
  • Multi-run ablation chains and one-factor-at-a-time probes; kept only changes that beat seed noise. A +0.77 dB result was traced to seed luck and dropped.
  • Checked generalisation on 109 unseen images from other cameras (LSRW, LOL-v2 new scenes).

M.Tech Research Ongoing

NFR-v4 + HVI on RetinexFormer: audit & from-scratch benchmark

Does a neighbourhood-attention refinement block really improve a state-of-the-art model when both are trained the same way?

What I did

  • Audited the earlier prototype: resizing test images to 256×256 had inflated PSNR by 1.3 dB, and the block crashed on non-square images.
  • Rebuilt a full-resolution evaluation that reproduces the published RetinexFormer result (25.16 dB / 0.845).
  • Redesigned the block: 4-head attention over its own patch plus 8 neighbours, relative-position bias, zero-initialised residual and an HVI-guided gate, with 59% fewer added parameters, verified by an automated CPU test suite.
  • Ran controlled A/B trainings from scratch: 150K iterations, official recipe, same seed, two runs in parallel on 2× T4 GPUs.
